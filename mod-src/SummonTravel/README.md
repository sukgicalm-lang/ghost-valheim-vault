# Ghost 해골 동행·방어막 표시 1.0.16

Ghost 통합팩 1.0.57에 포함됩니다. GhostR2 업데이트 완료 후 게임을 다시 실행하세요.

- 네트워크에서 아직 제거되지 않은 해골의 이름표를 즉시 감춥니다. 같은 네트워크 ID의 해골이 다시 로드되어도 해제 상태를 유지합니다. 몸체가 숨겨진 소유권 대기 중에는 이름표를 표시하지 않습니다.
- 해골을 소환한 뒤 인벤토리(Tab)를 열고 왼쪽 장비창 위의 **해골 소환 해제**를 누르면, 월드에 남은 내 소환 해골을 한꺼번에 해제합니다. 다른 구역에 저장된 해골만 있을 때도 누를 수 있도록 월드에서 인벤토리 버튼을 계속 표시합니다. 이미 진행 중인 소환은 취소됩니다. 멀티플레이에서 다른 구역의 개체까지 해제하려면 월드 호스트 또는 전용 서버도 업데이트해야 합니다.
- 새로 소환한 해골은 대기 명령 후에도 해제할 수 있습니다. 업데이트 전에 이미 대기 중이라 게임에 소환자 정보가 없는 해골은 먼저 다시 따라오게 하면 해제할 수 있습니다.

- 낙하 피해는 보호의 스태프 보호막 잔량부터 차감합니다. 피해 100에 보호막이 300이면 보호막은 200, 체력 피해는 0입니다. 보호막이 25면 보호막이 깨지고 체력 피해는 75입니다.
- 재소환 후 실제 개체와 연결이 끊긴 이름표는 화면에서 제거합니다. 게임의 이름표 목록에 등록되지 않고 HUD 아래에 남은 복제본도 정리합니다.

- 자동 복귀는 플레이어와의 직선거리가 100m 이상이거나, 따라가거나 물러나야 하는 해골이 실제 위치를 10초 이상 바꾸지 못할 때만 시도합니다. 정상 대기와 전투 시간은 걸림으로 세지 않습니다. 0.5m 이상 이동하면 타이머를 다시 셉니다. 검사는 0.5초 간격입니다.
- 20m 이상 뒤처진 비전투 해골은 기본 이동속도의 최대 6배로 빠르게 달려 합류합니다(걷기 25m/s, 달리기 40m/s 상한, 원래 더 빠르면 유지). 8m 안에 들어오면 원래 속도를 복원합니다. 전투·대기 명령·사망·소유권 변경·순간이동 보류·월드 정리 시에도 복원합니다. 좌표를 연속으로 옮기는 가짜 달리기는 쓰지 않습니다.
- 가까이 붙으면 바깥쪽으로 걸어 물러납니다. 가까워졌다는 이유만으로 4초 후 순간이동하던 처리는 제거했습니다. 실제로 움직이지 못한 경우에만 10초 기준을 적용합니다.
- 플레이어가 직접 쓰는 지도 순간이동과 포탈에는 기존 해골이 함께 이동합니다. 이는 100m·10초의 자동 복귀와 별개입니다. 플레이어의 원래 순간이동 완료·실패 위치를 따릅니다.
- 따라오는 살아 있는 소환 해골에 한해 기본 거리 초과 소환 해제를 보류해 100m 복귀 전에 사라지지 않게 합니다. 대기 명령·정상 사망·최대 소환 수·로그아웃 정책은 유지합니다.
- 도착 위치는 뒤쪽·옆쪽 우선이며 몸 사이 최소 1m 여유를 확인합니다. 바닥 높이·충돌·지역 로딩을 확인하고, 안전한 자리가 없으면 재시도합니다. 플레이어가 공중에 있을 때 자동 복귀하지 않습니다.
- 기존 개체를 이동하므로 체력·장비·등급·명령·방어막 흡수량과 남은 시간을 유지합니다. 새 소환·치유·버프 시간 연장을 하지 않습니다.
- 해골 방어막 누락 이펙트 복구는 유지합니다. 이펙트 복구는 프레임당 한 개체씩 처리하며 정상 이펙트는 다시 만들지 않습니다.
- 내 HP 막대의 화면 오른쪽, 같은 높이에 같은 모양의 파란 보호막 막대를 유지합니다. 회전된 세로 HP에서도 화면 오른쪽을 기준으로 배치하고 남은 수치를 간결하게 표시합니다. 음식에 따른 HP 크기·UI 배율을 따르며 소진·만료·사망·HUD 숨김 시 감춥니다.
- 여왕 등 보스 버프는 원래 HP와 버프 사이의 보이는 간격을 보호막 오른쪽에도 유지합니다. 아이콘과 실제 렌더링된 이름·대기시간 글자만 측정하고 큰 빈 컨테이너·텍스트 영역은 제외합니다. 고정 16px 여백을 더하지 않으며 UI 배율·세로 HP·음식에 따른 크기 변경에도 기본 간격 비율을 유지하고, 보호막이 사라지면 원래 위치를 복원합니다.
- 내 머리 위에는 방어막이 있는 동안 남은 시간만 표시합니다. 자신의 이름·HP·방어막 수치·막대·배경 패널을 표시하지 않습니다. 기능이 생성한 자기 이름표는 정리 시 제거해 이름만 남는 현상을 막습니다.
- 해골은 위에서부터 보호막 시간, 원래 이름, 현재 / 최대 HP, 방어막 잔량 / 최대치 순서입니다. 시간은 이름과 동일한 크기, HP·방어막 숫자는 이름의 85% 크기입니다. HP·방어막이라는 앞글자와 모든 막대·배경 패널을 없애고 원래 이름 텍스트만 복제합니다. 아군 해골은 30m 안에서 숫자를 계속 표시하며, 원래 이름·머리 위치·HUD 숨김을 따릅니다.
- 남은 시간은 m:ss 형식입니다. 실제 효과의 지속시간 - 경과 시간을 올림해 표시하며, 소진·만료 시 숨깁니다. 원격 해골은 기존 동기화 기록에 경과 시간을 차감합니다. 시간 표시를 읽는 행위로 효과·잔량·타이머를 갱신하지 않습니다. 이름 크기 변경을 따르고 값이 바뀔 때만 텍스트를 다시 씁니다.
- 해골 회복량은 따라가는 캐릭터가 먹은 음식의 회복량·회복 버프를 초당 HP로 계산합니다. Regeneration(aedenthorn.Regeneration)이 활성화돼 있으면 HealthRegenMult / HealthRegenTimeMult도 반영합니다. 기본 NPC 회복보다 빠른 경우에만 native BaseAI.UpdateRegeneration 호출 중 m_regenAllHPTime을 일시 조정하고, 성공·예외 모두 원래 값을 복구합니다. 먹이를 먹을 수 없는 소환 해골은 회복 호출 중에만 BaseAI.m_tamable 참조를 잠시 분리해 동물 배고픔 판정을 우회합니다. 성공·예외 모두 원래 참조와 회복 시간을 복구하며 먹이 기록·동물·야생·원격 비소유 개체는 변경하지 않습니다. 정상 회복 주기·최대 HP 제한·죽음·소유권 처리는 게임이 담당하며 순간이동 중에는 회복을 보류합니다. 대기 중인 로컬 소유 해골은 로컬 플레이어를 기준으로 하며, 원격 플레이어는 동기화된 회복량을 사용하고 15초 이상 오래된 값은 기본 회복으로 복귀합니다.
- 친구와 전용 서버도 같은 통합팩으로 업데이트해야 합니다.

## 한 번 시전으로 기존 해골 교체와 장비 분산

매번 현재 지팡이·숙련도 설정이 허용하는 최대 수의 새 해골을 소환합니다. 기존 해골 수를 빼지 않습니다. 새 해골의 원래 소환 과정에서 Tameable.Command → RPC_Command → UnsummonMaxInstances가 한도를 넘는 오래된 해골을 원래 네트워크 해제 방식으로 교체합니다. 예를 들어 한도가 4라면 기존에 4마리가 있거나 2마리만 살아 있어도 한 번 시전으로 새 4마리가 됩니다. 이전 해골을 미리 일괄 삭제하지 않으므로 소환 실패·취소 때 아직 교체되지 않은 해골은 남습니다. 다른 플레이어·야생·다른 생물·대기 명령의 한도 정책은 게임 원래대로입니다.

별도 개체 생성·강제 사망 코드를 추가하지 않습니다. 원래 스킬 능력치·등급·명령 RPC·이펙트·전역 개체 제한·시전 비용을 사용하며 생성 반경 최소 3m는 유지하되 개체별 생성 전 대기(m_preSpawnDelay)와 생성 사이 대기(m_spawnDelay)를 모두 0으로 설정합니다. 원래 공통 시전 대기(m_initialSpawnDelay)는 한 번만 유지하고 유효한 소환 위치에서는 전체 최대 수를 같은 프레임에 생성합니다. 위치 탐색 실패의 원래 재시도 대기는 유지합니다. 겹쳐 시전해도 각 시전은 새 최대 수를 요청하고 게임의 원래 명령 경로가 한도를 처리합니다.

이번에 새로 생성되는 해골끼리 무기 종류와 방패 유무를 고르게 배정합니다. 숙련도 항목이 모두 None인 NPC 무기도 실제 프리팹 이름과 무기 종류로 구분합니다. 원래 해골의 기본 장비·무작위 무기·장비 세트·확률 장비에 존재하는 무기만 후보로 사용하며 새 무기를 외부에서 추가하지 않습니다.

장비는 게임의 Humanoid.Start → GiveDefaultItems 단계에서 실제 생성됩니다. Awake 때 이번 배치의 실제 무기 프리팹을 배정하고, 생성 코루틴이 끝나거나 다음 프레임이 되어도 유지되는 별도 기록으로 보관합니다. GiveDefaultItems 직전에 해당 해골 인스턴스의 장비 목록만 조정해 선택한 무기를 기본 지급하고, 다른 무기가 추가로 무작위 지급되는 경로를 제거합니다. 원래 비무기 장비·갑옷·장식 및 기본 인벤토리 생성 과정은 유지합니다. 공유 원본 프리팹의 배열은 수정하지 않습니다.

실제 무기·방패 프리팹 이름을 ZDO에 저장해 친구·재접속에서도 같은 원래 장비를 사용합니다. 저장값은 그 해골의 현재 원래 후보 목록 안에서만 확인합니다. 난수 예측이나 외부 장비 추가에 의존하지 않으며, 아이템 생성 자체가 난수를 소비하더라도 배정 무기는 바뀌지 않습니다. 새 3마리와 허용된 무기 종류 3개가 있다면 3가지 종류를 배정합니다.

## 재소환 후 보이지 않는 해골 이름표·보호막 0 잔상 정리

Tameable.UnSummon 요청과 RPC_UnSummon 수신 시점에 실제 소환 해골을 즉시 해제 예정으로 표시합니다. 게임의 본체 파괴는 그대로 실행하지만, 그 전에 대기 중인 순간이동·장면 유지·물리 동결·추적 속도 보정·보호막 이펙트 복구 요청을 해제합니다. 해제 예정 개체에는 거리 소환 해제 예외·자동 복귀·보호막 복원·수치 갱신을 적용하지 않습니다. 플레이어·다른 동물은 건드리지 않습니다.

HUD 갱신 때 현재 Character 목록·유효한 네트워크 개체·생존 여부·해제 예정 여부·현재 HUD 연결을 함께 검사합니다. 본체가 사라졌거나 연결이 끊어진 이름표는 숫자만 없애지 않고 이름을 포함한 전체 GUI와 캐시를 한 번에 정리합니다. 같은 GUI가 다른 현재 해골에 연결됐다면 현재 GUI를 파괴하지 않고 해당 개체의 표시를 다시 구성합니다. 파괴가 프레임 끝에 실행되는 동안에도 옛 GUI와 행을 즉시 숨겨 겹쳐 보이지 않게 합니다.

이에 따라 기존 해골의 낮은 HP·보호막 0 이름표가 순간이동 전까지 남는 경로를 차단합니다. 현재 3마리의 실제 보호막·체력·충돌·원래 보호의 스태프 적용은 유지하며 가짜 보호막이나 추가 해골을 만들지 않습니다. 이 정리는 순간이동이나 거리 이탈을 기다리지 않습니다.

## 보호의 스태프 적용 반경 20m

보호의 스태프 시전 시 주변 아군에게 방어막을 주는 범위를 반경 20m(지름 40m)로 확장합니다. staff_shield_aoe의 Awake와 Setup에서 m_radius를 20으로 설정하고, 트리거 구체가 있으면 월드 배율을 반영해 같은 20m 반경으로 조정합니다. 캐릭터·아군·시전자 판정과 비용·방어막 수치·지속시간은 원래 시전 경로를 사용합니다. 시각 효과를 통째로 확대하지 않습니다.

보호의 스태프 효과만 변경하며 다른 마법·적의 범위 공격은 바꾸지 않습니다. 시전 후 멀어져도 이미 받은 방어막은 잔량·시간이 끝날 때까지 유지합니다. 친구·서버도 같은 버전으로 업데이트해야 같은 범위를 적용받습니다.

## 보호의 스태프 재시전 충전

이미 보호막이 있을 때 보호의 스태프를 정상 재시전하면, 게임이 이번 시전의 숙련도·월드 레벨로 계산한 최대 흡수량까지 다시 채웁니다. 예를 들어 현재 최대 300, 남은 55라면 재시전 후 300 / 300입니다. 300을 고정하지 않으며 숙련도가 올라 새 최대치가 350이면 350 / 350으로 표시합니다. 기존 방어막에 더해 중첩하지 않습니다.

이전 1.0.45~46 수정은 SEMan.Internal_AddStatusEffect 후처리에만 연결돼 있었습니다. 제공된 게임의 Character.RPC_Damage는 방어막이 이미 있으면 이 함수를 부르지 않고, 기존 효과의 ResetTime과 SetLevel을 직접 호출합니다. 따라서 본인·해골 재시전 모두 이전 후처리를 우회할 수 있었습니다. 효과 객체를 직접 받는 SEMan.AddStatusEffect 오버로드도 기존 후처리를 거치지 않습니다.

1.0.47부터 Staff_shield의 공통 ResetTime → SE_Shield.SetLevel 경로를 처리합니다. 같은 프레임에 시간 갱신과 최대치 계산이 끝난 실제 대상만 충전하며, 원격 비소유자·다른 효과·SetLevel 단독 호출·오래된 시간 갱신에는 개입하지 않습니다. 새 최대치를 계산한 뒤 소모 피해량을 초기화하고, 해골 스냅샷과 표시에도 반영합니다. 단순 HUD 읽기·순간이동 복원은 충전하지 않습니다. 본인·해골의 성공한 충전은 게임 로그에 한 줄씩 남깁니다.

회귀 검사는 실제 Harmony 2.4.2를 사용해 ResetTime/SetLevel을 가로챕니다. 기존 캐릭터 피격 경로에서 소모량이 유지되는 문제를 먼저 재현한 뒤, 같은 경로에서 본인·해골 모두 충전되는지 확인합니다. ID 적용·효과 객체 적용·숙련도 변경·타이머·자기 HUD·중첩 금지·비소유자·순간이동 보존도 실행합니다. 테스트용 Harmony 패키지는 설치 DLL에 포함하지 않습니다.

## 검은 로딩 화면·멈칫 수정 근거

게임 `ZNetScene.RemoveObjects`에 전달되는 임시 지역 목록은 `IsAreaReady`와 공유됩니다. 이전 장면 제거 패치가 이동 Tick을 다시 호출해 이 목록을 비우거나 다시 채울 수 있었습니다. 장면 제거 패치는 보류 중인 해골·이펙트만 목록에 추가하고, Tick·지역 준비 검사·전 캐릭터 탐색을 하지 않도록 분리했습니다. 저장은 실제 소환 해골의 `ZNetView.ResetZDO` 직전에 수행합니다. 플레이어의 순간이동 필드·검은 화면·목적지는 강제로 바꾸지 않습니다.

합류는 프레임당 한 개체, 위치 충돌 탐색은 전체 프레임당 최대 4후보로 제한하고 다음 프레임에 이어갑니다. 도착 좌표가 같으면 Rigidbody 위치와 강제 네트워크 전송을 반복하지 않습니다. 캐릭터 종류 판정을 캐시하고, 예외가 발생하면 묶어 둔 물리를 풀어 기본 이동 루프에 예외가 전파되지 않게 합니다.

## 검증·빌드

관리 코드 동작 검사 253개와 제공된 실제 게임 DLL의 API·패치·바이너리 검사 107개 통과. 별도의 실제 Harmony 실행 회귀 검사 39개는 CI에서 검증합니다. 실제 Valheim 월드에서 화면·프레임 시간·친구 PC·서버 동작은 실행하지 못했으며 실행 검증이 별도로 필요합니다. 제공된 Valheim 1.0.20 참조로 빌드했고 실제 이용 중인 1.0.21에서의 실행 확인은 별도입니다.

.NET Framework 4.8과 실제 assembly_valheim·UnityEngine·BepInEx·Harmony 참조로 결정적 Roslyn 빌드합니다. 프로젝트 빌드는 VALHEIM_MANAGED와 BEPINEX_PATH를 지정합니다. 동작 검사는 `dotnet run --project ../SummonTravel.Tests/Behavior.csproj --configuration Release`입니다. 게임 참조 DLL·테스트 doubles·개인 설정·세이브는 배포하지 않습니다.
